# 更新与维护

## 项目中的文件如何协作

`docs/` 是唯一正文源；`site/` 完全由脚本生成。`sources/manifest.json` 记录 PDF 身份与哈希，`sources/page-coverage.csv` 逐页记录文字、视觉和正文状态，`sources/knowledge.json` 提供稳定知识点索引。原始资料位于项目上一级，只读使用。

构建使用本地 marked 与 KaTeX，将数学编译进 HTML；无需网页运行时加载公式库，也无需 CDN。CSS、脚本、字体、图表一起打包，支持普通静态托管及直接打开本地页面。

## 新增课件流程

1. 把新课件保存在课程目录，保留文件名中的版本日期，不覆盖旧版。
2. 运行 `python scripts/inspect_sources.py`，先检查 `sources/changes.json`，保存本轮差异记录。脚本为新文件追加来源 ID，已有 ID 不重新排序。
3. 对比新增／变更页，逐页阅读定义、推导、图表、代码与作业；公式文本不完整时渲染原页，记录实际已查看的物理页码。
4. 更新受影响正文、`scripts/indexes.py` 中的人工页段映射、视觉状态和未完成事项；新版不能无理由覆盖旧版独有知识。
5. 重新生成索引、图表，执行数学检查、网站构建与链接检查；再做实际页面检查。
6. 内容有意识删改时，记录数学或教学理由，再审查并更新 `content-baseline.json`；不得自动重建基线来绕过失败。
7. 保存进度和验证结果。有 Git 仓库后再审查差异并提交；确认不包含原书、课件、缓存和敏感资料后部署。

## 基线的作用与局限

当前基线检查稳定锚点、章节长度的大幅减少和行间公式数量下降。它能发现一些意外删除，不能判断等长替换是否正确，也不能证明内容完整。来源覆盖审校仍是独立门禁。新增内容不应通过复制模板填充长度。

## GitHub Pages 部署准备

项目提供 `deploy/github-pages.yml` 模板。将 `教材` 目录作为独立仓库根目录后，把该模板放到 `.github/workflows/pages.yml`，提交源码、锁文件与基线，设置仓库 Pages 来源为 GitHub Actions。构建输出为 `site/`，不包括上一级原始 PDF。

CI 先安装 Python／Node 依赖，重建图表与索引，执行数学检查、构建和链接检查，再上传静态产物。发布仍不代表内容最终验收通过；首页的初稿与版本边界应保留，直至相关内容门禁关闭。
